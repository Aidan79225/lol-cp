# 出裝規劃：接近的替代選項

日期：2026-09-16
狀態：已核准，待實作
前置：`2026-09-14-build-optimizer-design.md`（規劃器評分與限制）

## 1. 問題

使用者質疑推薦（「達瑞文／煞蜜拉沒這麼吃攻速」）。實測第一件的分數差距：

```
煞蜜拉 空出裝（9 級）ΔDPS/千金：
  雲陶狂箭 44.6　無盡之刃 44.3　蒐集者 42.2        ← 第一名只贏 0.7%
```

**0.7% 的差距遠小於模型本身的誤差**（整場平均假設、操作假設、未建模的被動），
介面卻把它呈現成一個確定答案。這是目前最容易誤導人的地方。

## 2. 決策

| 決策 | 選擇 |
|---|---|
| 呈現方式 | 每一步列出分數差距在容忍範圍內的其他合法候選 |
| 比較基準 | 同一前綴下的**該步分數**（與規劃器同一條評分），非整段序列重規劃 |
| 容忍度／數量 | `config/build_planner.toml`：`alternative_tolerance = 0.03`、`max_alternatives = 3` |
| 不做 | 逐個候選重跑整段規劃（成本高；使用者要的是「這一步有哪些接近的選擇」） |

## 3. 定義

第 k 步選中件 `c*`，前綴 `P = 已排定的前 k−1 件`：

```
score(x) = 規劃器評分(P + x, levels[k−1])        # DPS × (EHP/裸裝EHP)^β
比例(x)  = score(x) / score(c*)
入列條件 = x 合法（群組上限、鞋位、不重複）∧ 比例(x) ≥ 1 − 容忍度 ∧ x ≠ c*
```

依比例由高到低排序，取前 `max_alternatives` 個。

## 4. 領域模型

```python
@dataclass(frozen=True)
class PlanAlternative:
    item: Item
    score_ratio: float      # 0.993 = 比選中的低 0.7%

# PlanStep 新增
alternatives: tuple[PlanAlternative, ...] = ()
```

在 `BuildPlanner.plan` 定序完成後計算；沿用既有的評分快取（同一集合只算一次）。

## 5. UI

規劃結果表新增「接近的替代」欄：`海妖殺手 −0.4%、無盡之刃 −1.2%`；無則顯示「—」。

## 6. 測試

- 容忍度邊界：恰在 3% 內入列、3.1% 不入列
- 數量上限 `max_alternatives`
- 合法性：同群組已滿者不入列；鞋位只列鞋、其餘位置不列鞋
- 排序由高到低、不含選中件本身
- 真資料黃金：煞蜜拉第 1 步的替代清單應包含無盡之刃（實測差 0.7%）

## 7. 效能

每步掃描一次候選（約 112 件 × 6 步），且與規劃階段共用評分快取 —— 預期可忽略；
仍以規劃器單次 ≤ 1 秒為驗收。
