# 出裝規劃：接近的替代選項

日期：2026-09-16
狀態：已實作（2026-09-16）
前置：`2026-09-14-build-optimizer-design.md`（規劃器評分與限制）

## 1. 問題

使用者質疑推薦（「達瑞文／煞蜜拉沒這麼吃攻速」）。實測第一件的分數差距：

```
煞蜜拉 空出裝（9 級）ΔDPS/千金：
  雲陶狂箭 44.6　無盡之刃 44.3　蒐集者 42.2        ← 第一名只贏 0.7%
```

**0.7% 的差距遠小於模型本身的誤差**（整場平均假設、操作假設、未建模的被動），
介面卻把它呈現成一個確定答案。這是目前最容易誤導人的地方。

## 2. 決策

| 決策 | 選擇 |
|---|---|
| 呈現方式 | 每一步列出分數差距在容忍範圍內的其他合法候選 |
| 比較基準 | **換件後整條序列的價值 V**（規劃器真正最佳化的量），其餘件不動 |
| 分級 | **兩級**：3% 以內標「接近」、8% 以內標「可考慮」（使用者 2026-09-16 選擇） |
| 容忍度／數量 | `config/build_planner.toml`：`near_tolerance = 0.03`、`consider_tolerance = 0.08`、`max_alternatives = 3` |
| 不做 | 逐個候選重跑整段規劃（成本高；使用者要的是「這一步有哪些接近的選擇」） |

## 3. 定義

規劃結果 `S = (c₁ … c₆)`，第 k 步的替代件 `x`：

```
S(x)     = 把 S 的第 k 件換成 x，其餘不動
比例(x)  = V(S(x)) / V(S)                      # V 為序列價值（持有期間加權）
入列條件 = x 不在 S 之中 ∧ S(x) 全程合法（群組上限、鞋位、不重複）
           ∧ 比例(x) ≥ 1 − consider_tolerance
分級     = 比例(x) ≥ 1 − near_tolerance ? 「接近」:「可考慮」
```

依比例由高到低排序，取前 `max_alternatives` 個。

### 3.1 校準：第一件其實沒那麼接近（2026-09-16 實測）

使用者原本的疑慮是「第一名只贏 0.7%」。改用序列價值衡量後：

| 容忍度 | 三隻英雄第 1 步的替代 |
|---|---|
| 3% | 全部「—」 |
| 8% | 煞蜜拉 −6.4%、達瑞文 −7.5%、凱爾 −（無） |

**0.7% 是單步視角的錯覺**：換掉第一件會連帶拉低後面每一步，且「便宜又強的件被加權更久」
的效果消失，整段代價是 6–10%。規劃器對「第一件」其實有把握；真正接近的選擇集中在
第 4 與第 6 步（差 1% 上下）。兩級顯示同時呈現這兩種情況。

> **為什麼不用「該步分數」比較（2026-09-16 實作時更正）**：初版以單步分數為基準，
> 真資料立刻照出問題 —— 煞蜜拉第 1 步列出「無盡之刃 **+8.3%**」：它單看這一步更強，
> 卻沒被選中，因為規劃器最佳化的是整條序列（先買便宜又強的件，其戰力被加權更久）。
> 以序列價值為基準後，替代一律為 0% 或負值，語意才是「改買這件，總價值少 x%」。

## 4. 領域模型

```python
class AlternativeTier(Enum):
    NEAR = "接近"        # 差距 ≤ near_tolerance
    CONSIDER = "可考慮"  # 差距 ≤ consider_tolerance


@dataclass(frozen=True)
class PlanAlternative:
    item: Item
    score_ratio: float      # 0.993 = 比選中的低 0.7%
    tier: AlternativeTier

# PlanStep 新增
alternatives: tuple[PlanAlternative, ...] = ()
```

在 `BuildPlanner.plan` 定序完成後計算；沿用既有的評分快取（同一集合只算一次）。

## 5. UI

規劃結果表新增「替代選項」欄：`鬼索 -0.7%（接近）、海妖殺手 -7.5%（可考慮）`；
無則顯示「—」。

## 6. 測試

- 容忍度邊界：恰在 3% 內入列、3.1% 不入列
- 數量上限 `max_alternatives`
- 合法性：同群組已滿者不入列；鞋位只列鞋、其餘位置不列鞋
- 排序由高到低、不含選中件本身
- 真資料黃金（以序列價值衡量後更正）：
  - **三隻英雄第 1 步皆無「接近」級替代** —— 第一件的選擇其實有把握
  - 達瑞文第 4 步的海妖殺手為「接近」（實測 −1.5%）
  - 替代清單不得出現已在計畫中的件

## 7. 效能

每步掃描一次候選（約 112 件 × 6 步），且與規劃階段共用評分快取 —— 預期可忽略；
仍以規劃器單次 ≤ 1 秒為驗收。
