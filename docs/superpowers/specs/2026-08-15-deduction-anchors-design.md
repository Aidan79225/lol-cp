# 扣除法錨定（Derived Anchors）設計

日期：2026-08-15
狀態：已與使用者確認設計，待實作
前置：主 spec `2026-08-12-lol-item-gold-efficiency-design.md` §5.3

## 1. 問題

權威法要求「每種屬性一件單一屬性基礎裝備」，但 16.15.1 沒有純吸血裝備——
最基礎的吸血鬼權杖（1053, 900g）也是「15 物攻 + 7% 吸血」複合件。因此
life_steal 在權威法永遠標「⚠ 未定價」，殞落王者之劍等 7 件帶吸血裝備的
權威 CP值 只是下限（BotRK 63.3%），而最小平方法早已給出 37.0/1%。

社群傳統解法是**扣除法**：權杖 900g 扣掉 15 物攻 ×35 = 375g，餘額歸給
7% 吸血 → **53.571g/1%**。本設計把扣除法帶進權威定價，機制通用、
設定驅動，這次只錨 life_steal。

## 2. 決策記錄

| 決策 | 選擇 | 理由 |
|---|---|---|
| 範圍 | 通用機制，先只錨 life_steal | 其他 9 種未定價屬性日後逐一爭論，每加一種只改設定 |
| 設定形狀 | 顯式 `deduct` 清單＋嚴格驗證 | Riot 改動錨定裝備屬性時大聲報錯，絕不靜默算錯 |
| 依賴深度 | 單層：`deduct` 只能引用純錨定屬性 | 循環不可能發生，免拓撲排序；現實場景夠用 |
| 驗證失敗 | 沿用 `AnchorItemMissingError`，訊息說明不符處 | 與現有錨定錯誤同一處理路徑：啟動即炸 |

## 3. 領域模型

`AnchorEntry` 加選配欄位：

```python
@dataclass(frozen=True)
class AnchorEntry:
    stat: StatKey
    item_id: int
    reason: str
    deduct: tuple[StatKey, ...] = ()   # 空 = 純錨定；非空 = 扣除錨
```

`CanonicalDeriver.derive` 改為兩趟：

1. **第一趟（純錨定）**：`deduct == ()` 的條目，算法不變（總價 ÷ 屬性量）
2. **第二趟（扣除錨）**：
   `單價 = (total_gold − Σ deduct 屬性量 × 第一趟單價) / 目標屬性量`

## 4. 設定格式

```toml
[life_steal]
item_id = 1053   # 吸血鬼權杖 (900 − 15AD×35) / 7% = 53.571 每 1%
deduct = ["ad"]
reason = "無純吸血基礎裝備。社群傳統扣除法：權杖扣掉物攻餘額歸吸血。"
```

`load_anchors` 解析 `deduct`（鍵名為 StatKey snake_case，未知鍵沿用
`UnknownStatKeyError` 報有效選項）。

## 5. 嚴格驗證（derive 時，任一不符即擲 `AnchorItemMissingError`）

1. **屬性集合恰好相等**：`{目標屬性} ∪ deduct` 必須等於該裝備的全部屬性。
   多一種（Riot 加了新屬性）或少一種（deduct 列了裝備沒有的）都算失敗。
2. **單層依賴**：`deduct` 中每種屬性必須是設定內的**純**錨定條目。
   引用扣除錨或未錨定屬性都失敗。
3. **殘額為正**：扣完必須 > 0。負值或零代表錨定假設崩壞，
   不產生荒謬單價。

## 6. 對黃金數值的影響（16.15.1）

- life_steal 權威單價 **375/7 ≈ 53.571**（NNLS 為 36.99；兩法分歧本身
  就是分析入口，維持並列呈現不合併）
- 權威法定價屬性 11 → **12** 種，未定價 10 → **9** 種（主 spec §5.3 同步改）
- 殞落王者之劍（3153）：63.3% → **80.0%**（2560.71/3200），殘差 1175 →
  **639.3**，未定價數 1 → 0。Marksman 與 Mage∪Marksman 的 life_steal
  權重分別為 1.0 與 max(0.0, 1.0)=1.0，故**三視角相同的敘事保持成立**
  （主 spec §8 敘事改為「低分來自被動未計價」）
- 吸血鬼權杖被鎖成恰好 100%、殘差 0——錨定的固有代價，寫入黃金測試
- 其餘帶吸血裝備（嗜血者、狂怒九頭蛇、水星彎刀、槍銅護脛、保衛者戰鎚）
  權威 CP值 全數上升，但不在黃金測試的 4 件固定樣本內

## 7. 連帶修正：殘差為零的措辭

吸血鬼權杖殘差恰為 0 會暴露既有的措辭缺陷：`residual_is_passive_value`
只分正負，0 會顯示「屬性本身已超值」。`DetailPanel.render_lines` 改為
三分支：

- 殘差 > 0：「殘差 +Ng（至少這些金幣花在被動效果上）」
- 殘差 < 0：「殘差 −Ng（屬性本身已超值）」
- 殘差 = 0：「殘差 0g（屬性恰好定價）」

domain 的 `residual_is_passive_value` 語意不變（`> 0`）。

## 8. 測試

- **domain（pricing）**：扣除錨 happy path（53.571）；裝備多出未列屬性；
  deduct 列了裝備沒有的屬性；deduct 引用非純錨定；扣後殘額 ≤ 0；
  `deduct=()` 條目行為與現行完全相同
- **infrastructure（toml_config）**：`deduct` 解析；未知鍵名報錯；
  省略 `deduct` 時為空 tuple
- **golden**：`test_canonical_prices` 加 LIFE_STEAL=375/7、UNPRICED 移除
  LIFE_STEAL、定價數 11→12；`test_golden_cp_values` 的 BotRK 三視角改
  (80.0, 639.3, 0, 0)；新增吸血鬼權杖 100%/殘差 0 黃金測試
- **presentation（widgets）**：殘差三分支措辭字串斷言

## 9. 非目標（YAGNI）

- 多層扣除遞迴（扣除錨引用扣除錨）
- 其他 9 種未定價屬性的錨定條目（機制就緒後是純設定工作）
- UI 標示「此單價來自扣除法」
- NNLS 側任何變動
